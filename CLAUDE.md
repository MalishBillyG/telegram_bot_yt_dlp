# CLAUDE.md — контекст проекта

Этот файл — рабочая память для Claude Code по данному репозиторию.
Здесь фиксируются важные архитектурные решения и изменения в боте,
которые не всегда очевидны из самого кода.

## О проекте

Telegram-бот на `aiogram` для скачивания видео/аудио с YouTube, TikTok и
Instagram через `yt-dlp`. Весь код живёт в одном файле `bot.py`. Подробности
по установке и запуску — см. `README.md`.

## Ключевые решения

- **Один файл `bot.py`** — проект маленький, разделение на модули пока
  не оправдано.
- **FSM (aiogram)** для управления диалогом: `waiting_for_url` →
  `choosing_type` → `choosing_quality`. Функция `reset_state()`
  централизует сброс состояния (введена в рефакторинге, см. журнал ниже).
- **Скачивание в отдельном потоке** (`asyncio.to_thread`) — `yt_dlp` синхронный
  и блокирующий, нельзя вызывать напрямую в асинхронных хендлерах.
- **yt-dlp не зафиксирован по версии** в `requirements.txt` — старые версии
  быстро ломаются из-за изменений на стороне YouTube. Обновлять через
  `make update`.
- **Файлы скачиваются в `downloads/<user_id>/`** и не коммитятся в git.
- **Хранение пользователей/аналитики — SQLite (`db.py` → `bot.db`)**. Каждый
  update трекается через `UserTrackingMiddleware` (outer middleware на
  `dp.update`), которая пишет/обновляет запись в таблице `users`
  (`first_seen`/`last_seen`). Скачивания логируются в таблицу `downloads`
  вручную — вызовом `db.log_download(...)` сразу после успешного скачивания
  в `audio_type_handler` и `quality_handler` (до отправки файла, чтобы
  считать скачивание засчитанным даже если отправка в Telegram не удалась).
- **Админ определяется одним `ADMIN_ID` в `.env`** — сравнение `user_id ==
  ADMIN_ID` в `is_admin()`. Если `ADMIN_ID` не задан (0), админ-команды
  недоступны никому. Команды `/admin_stats`, `/admin_users`, `/admin_top`
  для не-админов ничего не отвечают (не палят факт существования команд).
  Зарегистрированы в `bot.py` **до** catch-all `url_handler`
  (`StateFilter(None, ...)`), иначе он перехватывал бы текст команд первым.

## Журнал важных изменений

- **2addbe1** — добавлена логика скачивания файлов через yt-dlp.
- **cb7411b** — добавлен `Makefile` (setup/run/update/check/clean) и
  `requirements.txt` для управления окружением.
- **4014a39** — рефакторинг: введена функция `reset_state()` для унификации
  сброса FSM-состояния вместо повторяющегося кода в каждом хендлере.
- **fc8e1ee** — добавлено сообщение об ожидании ссылки.
- **(текущая правка)** — исправлен баг: после перезапуска процесса
  (`python3 bot.py`) бот переставал реагировать на ссылки, пока пользователь
  не нажимал `/start`. Причина: `MemoryStorage` (FSM) сбрасывается при
  рестарте в состояние `None`, а `url_handler` требовал строго
  `waiting_for_url`. Фикс — `StateFilter(None, DownloadState.waiting_for_url)`.
  Также добавлен `bot.delete_webhook(drop_pending_updates=True)` перед
  `start_polling`, чтобы не разгребать очередь старых апдейтов после простоя.
- **(текущая правка)** — добавлен админ-функционал: новый модуль `db.py`
  (SQLite: таблицы `users`, `downloads`), `UserTrackingMiddleware` для
  трекинга активности всех пользователей, логирование скачиваний, команды
  `/admin_stats`, `/admin_users`, `/admin_top` (доступ по `ADMIN_ID` из
  `.env`). `db.init_db()` вызывается в `main()` при старте.
- **(текущая правка)** — в таблицу `downloads` добавлена колонка `url`
  (сама скачанная ссылка, не только платформа/тип). `init_db()` делает
  `ALTER TABLE downloads ADD COLUMN url` для баз, созданных до этой правки
  (проверено на симуляции старой схемы — миграция идемпотентна благодаря
  проверке через `PRAGMA table_info`). Добавлена команда `/admin_links
  <user_id>` — последние 20 ссылок конкретного пользователя.
- **(текущая правка)** — пользователю больше не показывается сырой текст
  исключений. Добавлены `report_error()`/`notify_admin()`: при любой ошибке
  (скачивание, получение инфо, отправка файла, а также любое необработанное
  исключение через глобальный `@dp.errors()`) пользователь видит нейтральное
  сообщение (`GENERIC_ERROR_TEXT`), а полный traceback + контекст (user_id,
  url) уходит админу в личку через `bot.send_message(ADMIN_ID, ...)`.
  Также добавлена проверка размера файла перед отправкой (`MAX_FILE_SIZE =
  20 MB`) — если скачанный файл больше лимита, отправка не предпринимается
  (всё равно упала бы на стороне Telegram), пользователю сообщается явно,
  для видео — с советом выбрать качество ниже.
- **(текущая правка)** — добавлена опциональная поддержка своего
  [Local Bot API Server](https://github.com/tdlib/telegram-bot-api) через
  `.env`-переменные `BOT_API_SERVER` и `BOT_API_LOCAL` (бот и сервер — одна
  машина, см. README). Если `BOT_API_SERVER` задан — `Bot` создаётся с
  `AiohttpSession(api=TelegramAPIServer.from_base(..., is_local=BOT_API_LOCAL))`.
  Если не задан — поведение не меняется (обычный `api.telegram.org`, лимит
  20 MB). `MAX_FILE_SIZE` подстраивается под режим: 20 MB
  (`api.telegram.org`) / 2000 MB (свой сервер без `--local`, файл всё ещё
  грузится по HTTP) / 4000 MB как условный потолок при `BOT_API_LOCAL=true`
  (файл вообще не грузится по HTTP — сервер читает его с диска сам).
  Добавлена `make_input_file()` — в `--local`-режиме отдаёт `str(Path(...).resolve())`
  вместо `FSInputFile`, т.к. aiogram (проверено на 3.30, `AiohttpSession.build_form_data`)
  всегда читает и грузит `FSInputFile` через multipart сам, `is_local` на
  `TelegramAPIServer` этого не меняет — путь как строку нужно передавать
  вручную, чтобы реально воспользоваться local-режимом сервера. Из-за этого
  же `DOWNLOAD_DIR` теперь строится от `Path(__file__).resolve().parent`, а
  не от относительного `Path("downloads")` — telegram-bot-api как отдельный
  процесс может быть запущен с другим cwd, и относительный путь означал бы
  для него другое место на диске.
- **(текущая правка)** — добавлена кнопка "Меню" в Telegram-клиенте:
  `setup_commands()` вызывается в `main()` перед `start_polling` и делает
  `bot.set_my_commands(...)` (только `/start` в дефолтном scope —
  `BotCommandScopeDefault()`, чтобы обычным пользователям не палить
  админ-команды) + отдельно `/admin_*` в scope `BotCommandScopeChat(chat_id=ADMIN_ID)`
  (работает, т.к. в личных чатах chat_id == user_id), плюс явный
  `bot.set_chat_menu_button(menu_button=MenuButtonCommands())`.
- **(текущая правка)** — добавлена поддержка Instagram: `get_platform()`
  распознаёт `instagram.com`/`instagr.am` и возвращает `"instagram"`.
  Отдельной ветки в `download_video()` не понадобилось — instagram, как и
  tiktok, попадает в `else`-ветку (`format=format_id` без merge с
  bestaudio), т.к. yt-dlp обычно отдаёт для Instagram уже смукшированные
  форматы (видео+аудио вместе), в отличие от YouTube.
- **(текущая правка)** — добавлена опциональная поддержка cookies для
  Instagram через `.env`-переменную `INSTAGRAM_COOKIES_FILE` (путь к
  cookies.txt в формате Netscape). Хелпер `cookies_options(platform)`
  возвращает `{"cookiefile": ...}` только для `platform == "instagram"` и
  только если файл реально существует на диске — иначе пустой dict, без
  падения. Подмешивается через `**cookies_options(platform)` в опции
  `yt_dlp.YoutubeDL` во всех трёх местах, где он вызывается:
  `get_video_info()`, `download_video()`, `download_audio()` — из-за этого
  у `get_video_info()` и `download_audio()` появился обязательный параметр
  `platform` (раньше его не было, т.к. поведение не зависело от платформы).
  Без `INSTAGRAM_COOKIES_FILE` поведение не меняется — анонимный доступ,
  как и раньше. В `.gitignore` добавлено `*cookies*.txt`, чтобы файл с
  сессией не попал в git по недосмотру (это фактически чувствительные
  данные уровня пароля от аккаунта).
- **(текущая правка)** — смягчена нестабильная ошибка TikTok `Unable to
  extract universal data for rehydration` (открытый баг yt-dlp/TikTok без
  фикса, см. https://github.com/yt-dlp/yt-dlp/issues/17332 — воспроизводится
  даже на последней версии yt-dlp, апдейт не помогает). По наблюдениям из
  этого issue ошибка интермиттентная и чаще ловится на ссылках с
  трекинг-хвостом (`?_r=...&_t=...`). Добавлена `normalize_url(url,
  platform)` — обрезает query/fragment у полных `tiktok.com`-ссылок
  (короткие `vt.tiktok.com`/`vm.tiktok.com` не трогает, вызывается в
  `url_handler` до сохранения в FSM).
- **(текущая правка)** — добавлен `extract_with_retry(ydl, url, download)` —
  обёртка над `ydl.extract_info()`, при любом исключении повторяет попытку
  до 2 раз (`RETRY_ATTEMPTS`) с паузой 3 секунды (`RETRY_DELAY`), **для всех
  платформ** (не только TikTok — сознательное решение: сетевые и подобные
  временные сбои у yt-dlp бывают не только на TikTok, различать платформы и
  текст ошибки не стали ради простоты). Используется во всех трёх местах
  вызова `extract_info()`: `get_video_info()`, `download_video()`,
  `download_audio()`. Побочный эффект: любая по-настоящему постоянная ошибка
  (приватное видео, неверный URL и т.п.) теперь показывается пользователю
  на ~6 секунд позже прежнего — это два лишних неудачных прохода перед тем,
  как исключение наконец поднимется.

- **(текущая правка)** — `make run` (`Makefile`) теперь умеет сам поднимать
  `telegram-bot-api` перед запуском бота, если в `.env` заданы
  `BOT_API_LOCAL=true` и новые переменные `TG_API_ID`/`TG_API_HASH`, а
  бинарник `telegram-bot-api` есть в `PATH`: запускается в фоне с
  `--local --http-ip-address=127.0.0.1 --http-port=<порт из
  BOT_API_SERVER>`, лог пишется в `telegram-bot-api.log`, и гасится через
  `trap ... EXIT` при остановке бота (`Ctrl+C`). Если условия не
  выполняются — `run` просто печатает предупреждение (если `BOT_API_LOCAL=
  true`, но чего-то не хватает) и запускает только `bot.py`, как раньше.
  `TG_API_ID`/`TG_API_HASH` читает только `Makefile` (через `. ./.env` в
  самом recipe) — `bot.py` их не использует и не парсит, они не относятся
  к рантайму бота, только к запуску сервера. Реализовано как одна recipe-
  строка с `\`-продолжениями (а не через `.ONESHELL:`), чтобы не менять
  поведение остальных таргетов `Makefile` (`setup`/`check` полагаются на
  построчный `@`-префикс).
- **(текущая правка)** — исправлен баг `make_input_file()` в `--local`-режиме:
  при отправке видео/аудио падало `TelegramBadRequest: invalid file HTTP
  URL specified: URL host is empty`. Причина — функция отдавала `telegram-
  bot-api` голый абсолютный путь (`str(Path(path).resolve())`), а серверу
  в `--local`-режиме, как оказалось (см. официальный README:
  "Upload files using their local path **and the file URI scheme**"),
  нужна именно `file://`-схема — без неё путь трактуется как обычный
  HTTP(S) URL и падает на пустом хосте. Подтверждено вручную через `curl
  -F "document=<path>"` напрямую к локальному серверу (тот же баг,
  `chat_id`/`document` без `file://`), затем с `file://`-префиксом —
  успех. Фикс — `Path(path).resolve().as_uri()` вместо ручной сборки
  строки (заодно корректно percent-encode’ит путь, если в нём когда-нибудь
  окажутся пробелы/юникод).

## Известные ограничения / TODO

- Нет автоочистки папки `downloads/` — файлы копятся на диске, в том числе
  те, что превысили `MAX_FILE_SIZE` и не были отправлены.
- `MAX_FILE_SIZE` (20 MB) проверяется постфактум, после полного скачивания —
  для видео можно было бы сразу отсеивать заведомо слишком тяжёлые качества
  в `quality_keyboard()`, но `filesize` там известен только для видеодорожки
  (без учёта аудио, которое подклеивается при мерже), поэтому оценка на
  этом этапе не точна.
- Обработка ошибок yt-dlp показывает пользователю сырой текст исключения.
