# CLAUDE.md — контекст проекта

Этот файл — рабочая память для Claude Code по данному репозиторию.
Здесь фиксируются важные архитектурные решения и изменения в боте,
которые не всегда очевидны из самого кода.

## О проекте

Telegram-бот на `aiogram` для скачивания видео/аудио с YouTube и TikTok
через `yt-dlp`. Весь код живёт в одном файле `bot.py`. Подробности по
установке и запуску — см. `README.md`.

## Ключевые решения

- **Один файл `bot.py`** — проект маленький, разделение на модули пока
  не оправдано.
- **FSM (aiogram)** для управления диалогом: `waiting_for_url` →
  `choosing_type` → `choosing_quality`. Функция `reset_state()`
  централизует сброс состояния (введена в рефакторинге, см. журнал ниже).
- **Скачивание в отдельном потоке** (`asyncio.to_thread`) — `yt_dlp` синхронный
  и блокирующий, нельзя вызывать напрямую в асинхронных хендлерах.
- **yt-dlp не зафиксирован по версии** в `requirements.txt` — старые версии
  быстро ломаются из-за изменений на стороне YouTube. Обновлять через
  `make update`.
- **Файлы скачиваются в `downloads/<user_id>/`** и не коммитятся в git.
- **Хранение пользователей/аналитики — SQLite (`db.py` → `bot.db`)**. Каждый
  update трекается через `UserTrackingMiddleware` (outer middleware на
  `dp.update`), которая пишет/обновляет запись в таблице `users`
  (`first_seen`/`last_seen`). Скачивания логируются в таблицу `downloads`
  вручную — вызовом `db.log_download(...)` сразу после успешного скачивания
  в `audio_type_handler` и `quality_handler` (до отправки файла, чтобы
  считать скачивание засчитанным даже если отправка в Telegram не удалась).
- **Админ определяется одним `ADMIN_ID` в `.env`** — сравнение `user_id ==
  ADMIN_ID` в `is_admin()`. Если `ADMIN_ID` не задан (0), админ-команды
  недоступны никому. Команды `/admin_stats`, `/admin_users`, `/admin_top`
  для не-админов ничего не отвечают (не палят факт существования команд).
  Зарегистрированы в `bot.py` **до** catch-all `url_handler`
  (`StateFilter(None, ...)`), иначе он перехватывал бы текст команд первым.

## Журнал важных изменений

- **2addbe1** — добавлена логика скачивания файлов через yt-dlp.
- **cb7411b** — добавлен `Makefile` (setup/run/update/check/clean) и
  `requirements.txt` для управления окружением.
- **4014a39** — рефакторинг: введена функция `reset_state()` для унификации
  сброса FSM-состояния вместо повторяющегося кода в каждом хендлере.
- **fc8e1ee** — добавлено сообщение об ожидании ссылки.
- **(текущая правка)** — исправлен баг: после перезапуска процесса
  (`python3 bot.py`) бот переставал реагировать на ссылки, пока пользователь
  не нажимал `/start`. Причина: `MemoryStorage` (FSM) сбрасывается при
  рестарте в состояние `None`, а `url_handler` требовал строго
  `waiting_for_url`. Фикс — `StateFilter(None, DownloadState.waiting_for_url)`.
  Также добавлен `bot.delete_webhook(drop_pending_updates=True)` перед
  `start_polling`, чтобы не разгребать очередь старых апдейтов после простоя.
- **(текущая правка)** — добавлен админ-функционал: новый модуль `db.py`
  (SQLite: таблицы `users`, `downloads`), `UserTrackingMiddleware` для
  трекинга активности всех пользователей, логирование скачиваний, команды
  `/admin_stats`, `/admin_users`, `/admin_top` (доступ по `ADMIN_ID` из
  `.env`). `db.init_db()` вызывается в `main()` при старте.

> При внесении значимых изменений в бота (новая платформа, новый формат,
> изменение FSM, смена структуры хранения файлов и т.п.) — дополнять этот
> журнал новой записью с кратким описанием "что и зачем".

## Известные ограничения / TODO

- Нет ограничения на размер файла перед отправкой в Telegram (лимит Bot API
  на загрузку файла — 50 MB для ботов).
- Нет автоочистки папки `downloads/` — файлы копятся на диске.
- Обработка ошибок yt-dlp показывает пользователю сырой текст исключения.
